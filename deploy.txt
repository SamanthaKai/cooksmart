Deploy the latest CookSmart changes to production.

1. Run the meal_plan table migration on the Railway PostgreSQL production database:
CREATE TABLE IF NOT EXISTS meal_plan (
    id SERIAL PRIMARY KEY,
    user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    recipe_id INT NOT NULL REFERENCES recipes(id) ON DELETE CASCADE,
    day_of_week VARCHAR(10) NOT NULL CHECK (day_of_week IN ('Monday','Tuesday','Wednesday','Thursday','Friday','Saturday','Sunday')),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, recipe_id, day_of_week)
);

2. Push all frontend changes to GitHub. Vercel will auto-deploy from the main branch.

3. Push all backend changes to GitHub. Railway will auto-deploy from the main branch.

4. After deployment, verify the following work on cooksmart-seven.vercel.app:
- Meal plan page loads
- Add to Meal Plan button works on recipe detail page
- Shopping list displays grouped by recipe
- WhatsApp share button appears at the bottom of recipe detail page
- Tribe/community tags are removed from recipe cards in the browse grid
